# 見積もり項目 出力ルール

## 3階層構造

見積もり項目は以下の3階層で構成する。

| 階層 | 粒度 | 例 |
|------|------|----|
| 大項目(カテゴリ) | 機能領域 | 認証機能、商品管理、決済 |
| 中項目 | feature単位 | ログイン、パスワードリセット、ソーシャル認証 |
| 小項目 | 実装詳細・テスト・選択肢 | フォームバリデーション、API連携、テスト・QA |

## テスト・QA の扱い

- テスト・QAは独立カテゴリにしない
- 各**中項目の末尾に小項目として**含める
- 例: `| | | テスト・QA | 正常系・異常系・境界値テスト | |`

## 出力方針: 網羅的に多めに出す

- **漏れより過剰を許容する** -- 人間が取捨選択する前提で出力する
- 想定される項目は積極的に列挙する。「明らかに不要」以外はすべて出す
- 判断に迷う項目は `※要確認` `※選択肢あり` を付けて出す
- 選択肢がある場合は小項目に併記する(例: `Google / Apple / LINE ※要確認`)
- 特筆すべき技術的考慮点や注意点も小項目として記載する

## 工数列

- `工数(h)` 列は **空欄** にする(テックリードが後から記入)
- 各カテゴリの末尾に小計行 `| **小計** | | | | |` を設ける
- 最後に総計行を設ける

## 未確定項目の扱い

- 未確定の仕様に依存する項目には `※` と注釈を付ける
- 技術スタックが未確認の場合は `[技術スタック: 要確認]` と記載し、未確定事項にも追記する

## バッファ

- デフォルト **20%**
- 引数や資料中に「バッファ○%」「リスク高め」等の記載があればその値・判断に従って調整する

## テーブル表現

```markdown
## N. [大項目名]

| # | 中項目 | 小項目 | 概要・選択肢 | 工数(h) |
|---|--------|--------|-------------|---------|
| N-1 | [feature名] | [実装詳細1] | [概要] | |
| | | [実装詳細2] | [概要] | |
| | | テスト・QA | [テスト観点] | |
| N-2 | [feature名] | [実装詳細1] | [概要] | |
| | | テスト・QA | [テスト観点] | |
| **小計** | | | | |
```
